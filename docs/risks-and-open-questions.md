## Assumptions

- EOD-only data is sufficient for the target user's decision process.
- A public scraping source can supply S&P 500 daily OHLCV at acceptable reliability for a proof of concept.
- ~500 tickers/day is a workload a single modest host can handle.
- Deterministic indicator Signals are the right first slice; geometric patterns are genuinely later work.
- The `alphapulse/` prototype's visual language is acceptable as the product direction.

## Risks

- **Scraping fragility / blocking:** source markup changes, IP bans or throttling can break ingestion; mitigated by throttling, retries, run logs and re-run.
- **Holiday-list drift:** the daily EOD schedule skips a committed NYSE holiday snapshot (`config/ingestion.php`), not a computed calendar, so it must be refreshed annually. A missing holiday causes a harmless idempotent run attempt (bars/snapshots unchanged, signals recomputed), not bad data.
- **Production scheduler / overlap lock:** `ingestion-scheduler` only defines the schedule; production still needs a host cron / Windows Task Scheduler entry running `php artisan schedule:run` (deployment concern). Overlap protection needs a lock-capable cache store (`database`/`array`); a crashed run holds the command lock until `INGESTION_LOCK_TTL_SECONDS` (default 7200s).
- **Source readiness at close + buffer:** at `16:30` the EOD bar may not be published yet, so a run with zero new bars is a normal, idempotent outcome rather than a bug.
- **Stooq anti-bot block (observed 2026-10-01):** `GET https://stooq.com/q/d/l/?s=nvda.us&i=d` returns an HTML SHA-256 proof-of-work challenge from this environment, not CSV. The engine now falls back to the reachable Yahoo Finance chart endpoint; live `GET /eod/NVDA` returned 501 daily bars and Laravel stored them. The fallback is not a completed licensing or scale decision: validate Yahoo terms, coverage and rate limits before operating all 503 tickers daily.
- **Market Context ETFs share the data-source risk (2026-10-22, `market-context-sectors`):** SPY and the 11 SPDR sector ETFs come through the same unofficial Yahoo/Stooq path as the stocks, so publishing their readings carries the same pending licence question. A failed ETF ingestion is isolated from the stock pipeline; the default `market-context:compute` recomputes the last 5 sessions so a one-day gap heals. The oldest dates of the one-year backfill may have null new highs/lows (they need 251 prior sessions).
- **Cboe put/call ratio terms (2026-10-22, planned `options-put-call`):** the ratio is not on FRED; the only free source is Cboe's public daily statistics page, whose website terms and data agreements limit use to personal or internal purposes. The feature ships disabled (`PUT_CALL_ENABLED=false`) and is enabled in production only after written permission from Cboe or with a licensed source; OCC's all-exchange report is the fallback if its terms are clearer. Scraping the page is also fragile.
- **FRED terms (2026-10-22, `macro-series-fred`):** before the first public display (`market-context-ui`) the page must show "This product uses the FRED® API but is not endorsed or certified by the Federal Reserve Bank of St. Louis.", link to the FRED API Terms of Use and name each series' source, and Chartiko's own terms of use must state that users agree to be bound by the FRED API terms. FRED also forbids using its content with AI/machine-learning systems, so macro data never reaches the AI provider.
- **FRED terms and the withheld legal notice (2026-10-23, `market-context-ui`):** Chartiko's terms of use are part of the legal notice, which stays withheld until a NIF and an address exist. `market-context-ui` adds the FRED clause to the terms ("Condiciones de uso") and a sources paragraph, shown while `market_context` is on, and shows the notice, the Terms of Use link and an explicit binding sentence on `/mercado` itself. The page and API ship behind `MARKET_CONTEXT_PUBLIC=false` (Admin preview). **Owner decision 2026-10-23: option (b)** — the flag stays off until the legal notice is published; options (a) on-page clause as interim terms and (c) a separate terms page were not chosen.
- **Market Context is Registered-only; paid plan later (2026-10-23, `market-context-patterns`):** owner decision "quiero que la parte de mercado solo este accesible a usuarios registrados, a futuro quiero establecer algunas de las funcionalidades de pago". Every Market Context surface (page, APIs, chart strip, pattern chips, Screener sector filters, their Saved Screeners, alerts and NL use) goes through the single `view-market-context` ability, so a future paid plan changes one closure; no plan, billing or upgrade UI exists yet (out of scope). Open: which features become paid. Risks: the capability is read at page load, so a flag flip reaches open tabs on their next load; a Saved Screener alert with sector filters is skipped (not notified) while its owner lacks access, which the owner sees only as silence; sector context uses the latest snapshot, not the pattern's date (umbrella "Later").
- **FRED series licences (2026-10-22):** `NFCI` (Chicago Fed, non-commercial reproduction only) ships off until the owner gets written permission; `VIXCLS` (Cboe copyright) ships off until Cboe's terms are cleared. The OECD CLI is included as `USALOLITOAASTSAM` (current, CC BY 4.0) but FRED shows no next release date: if it is discontinued, staleness hides it. Curve spreads are computed locally from H.15 yields and may differ from FRED's `T10Y*` by about 0.01 pp.
- **FRED real-data smoke pending (2026-10-22):** tests use recorded fixtures only; no FRED key exists in development. The owner has set the key and `MACRO_ENABLED=true` by hand in production, so the first run after deploy backfills 5 years by itself. Check `macro_series.last_error` after it: a units or JSON detail that differs from the documented API shape shows up there (`units_changed`, `invalid_response`) without affecting the pipeline. Spot-check a few readings against the FRED pages.
- **Market Regime thresholds and coverage (2026-10-22, `market-regime`):** every threshold in `MarketRegimeRules` is an uncalibrated initial value (calibration is a later task; record the production label distribution after the first run). While NFCI and VIXCLS stay off, production has at most 5 of 7 components, so `favourable`/`adverse` need +3/−3 from 4–5 components, and with `MACRO_ENABLED=false` the label is always `insufficient`. History starts at the first Breadth Snapshot (2025-10-22 in production; ETF bars cover about 2 years, so sector trends exist only from about Aug 2025). The backfill is point-in-time by publication date only: macro values are the latest vintage (no ALFRED), so backfilled history uses revised values, and bars can be re-adjusted by the source. If macro data was missing on the first post-deploy run, the seeded year is `insufficient` until `market-regime:compute --from=2025-10-22` is rerun.
- **Central bank calendar upkeep:** `config/central_banks.php` is hand-kept (FOMC 2027 dates are tentative until confirmed); `CentralBankCalendarTest` fails 60 days before either bank runs out of dates.
- **Incorrect math presented as signals:** indicator and Signal bugs would mislead users; mitigated by fixture-based tests.
- **Scope creep back to the mockup:** the prototype shows AI, alerts, plans and geometric patterns that are explicitly out of MVP scope.
- **Licensing of charts/data:** embedding third-party widgets or redistributing scraped data may carry legal constraints. Concrete residual for the chart: `lightweight-charts` is Apache-2.0 and its NOTICE requires the TradingView attribution link on the page showing the chart, so the chart's `layout.attributionLogo` must stay enabled and future chart surfaces must keep it visible.
- **Trust/positioning:** users may treat output as financial advice; the product must state it is an analytical tool.
- **AI Company Card text (updated 2026-10-15 by `company-fundamentals-sec`):** figures now come from SEC filings, not the model (`company-card-v2` has no metrics). Residual: the outlook and description are still AI-written and may misread or contradict the given figures or drift toward advice-like wording; mitigated by the v3 prompt, strict schema, permanent AI labelling and no targets/ratings, not machine-checked.
- **SEC fundamentals coverage and approximations (2026-10-15):** concept chains were validated on AAPL, MSFT, JPM, XOM, GOOGL (fixtures) and PLD (research); other filers may yield `missing_data`/`partial` (provenance in `inputs`; run a null-count report after the backfill). TTM EPS from YTD arithmetic, ROIC on period-end capital, D&A from `Depreciation` + intangibles and multi-class market cap priced with one class's close are documented approximations. Companyfacts can lag submissions by a quarter (`pending_*` shown in the UI).
- **SEC CIK reorganizations (observed 2026-10-15):** the live SEC ticker map already points XOM to a new holding company (CIK 2115436, ExxonMobil Holdings Corp) whose companyfacts only holds its first 10-Q, so the TTM cannot be computed there yet (expect `partial`/`missing_data` for XOM until it files a 10-K), while the old CIK 34088 keeps a permanent "pending" 10-Q. Similar holding-company moves can happen to other filers; a follow-up could fall back to the predecessor CIK.
- **SEC access (2026-10-15, contact set 2026-10-17):** production `SEC_USER_AGENT` is "Chartiko Roberto Rodriguez contacto@chartiko.com", installed by `deploy/configure-fundamentals-env.py` on every deploy. A `403` from the SEC stops the run; check the contact first. The owner must keep the `contacto@chartiko.com` mailbox reachable, because the SEC may use it.
- **AI Company Card cost and operations (2026-10-15):** every generation is a paid, synchronous call (timeout 40 s, below nginx's 60 s). Bounded by reuse (7-day freshness per Instrument and language), 5/min per user, 10/day per user and 200/day overall. Decided 2026-10-16: DevExpert Inference (`chat`), technical market data allowed (public data), default limits. The privacy policy names DevExpert Inference and TypeSafe AI (Jev); no personal data reaches either provider. The key comes from the GitHub `production` secret `AI_API_KEY`, installed by `deploy/configure-ai-env.py`. Still open: real cost per card on this provider. Metrics now come from SEC filings (`company-fundamentals-sec`), not the model. See `docs/ai-company-card-operations.md`.

- **Natural-language Screener (2026-10-19):** *prompt injection* is bounded by the enumerated `screener-query-v1` schema and `ScreenerFilterParser` (no tools, no data access, plain-text rendering): the worst case is a valid but odd filter set, which the user sees and can undo. *Cost*: one short call (max 800 tokens) per uncached request, capped at 6/min and 30/24 h per user and 600/24 h overall, with a 24 h cache of identical requests. *Model quality* on DevExpert `chat` is unverified until the production smoke (10 sample queries in the spec); tune the prompt with a version bump, not the schema. *Privacy*: users may type personal data; the text is never stored or logged, and the privacy policy and the input hint ask them not to.
- **Brevo opening pixel and mail authentication (updated 2026-10-24):** `alerts-email-golive` passed a disposable production registration, verification and digest flow, but the received message contained a Brevo opening pixel despite text-only API content and pixel consent `false`. The owner explicitly accepted that pixel and requested both email flows be activated. The privacy policy and first-layer notices disclose it; Chartiko does not request or use individual open/click events. Whether Brevo's remaining pixel processing qualifies for an exemption needs professional review. The temporary inbox reported SPF/DKIM false, but a later Brevo-to-Cloudflare test to `contacto@chartiko.com` was forwarded and delivered with SPF/DKIM pass. Destination inbox placement was not inspected. See `docs/specs/alerts-email-golive.md`.
- **No email change or password reset (2026-10-19; updated 2026-10-24):** both need dedicated, verified flows that are not part of `alerts-email-golive`. Until then an email change goes through the contact email and a forgotten password has no self-service recovery.
- **Registration email abuse and Brevo's daily cap (2026-10-23):** once verification is live, every sign-up and resend sends an email, so a script could mail many addresses and spend Brevo's free ~300/day. Mitigated by `throttle:10,60,register` per IP, `throttle:6,60` resend per user plus a 60 s SPA cooldown, and an email with no user-supplied text. Residual: distributed sign-ups from many IPs; never-verified accounts are not pruned (owner open question; they hold only name, email and hash and can be deleted by the user).
- **Session row after sign-out (observed 2026-10-19, fixed 2026-10-19):** `POST /api/logout` on the `database` session driver used to write the new, empty session row with the signed-out user's id (the cached Sanctum guard was the default guard when the session was saved). `AuthController::logout` now calls `Auth::guard('sanctum')->forgetUser()`, as account deletion does; `AccountSelfServiceTest::test_signing_out_leaves_no_session_row_for_the_user` covers it.
