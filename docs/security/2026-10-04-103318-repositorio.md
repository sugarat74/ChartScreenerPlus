## 6. Hallazgos priorizados

### SEC-001 — Usuario web puede reemplazar la activación de releases

- **ALTA / P0 / bloquea publicación mediante estos scripts.** FILE-04.
- Hecho: setup-server.sh:27–28 deja el directorio `/var/www/alphapulse` con grupo www-data y escritura de grupo; servicios ejecutan como www-data. E-002,012.
- Impacto condicionado: tras comprometer el proceso web/engine, se puede reemplazar el enlace current por estar su padre escribible, logrando persistencia y ejecutar otro código en siguientes cargas/reinicios. No es necesario demostrar que cada archivo de una release sea escribible. No se han consultado ACL del VPS.
- Corrección: directorio raíz, releases y enlaces de activación controlados únicamente por deploy; www-data solo lectura/traversal. Escritura de servicio limitada a storage, bootstrap/cache y ubicación privada de SQLite y sus archivos auxiliares. Separar usuario del engine si no necesita datos de Laravel.
- Responsable propuesto: operaciones; antes del primer despliegue.
- Cierre: verificar ownership/modos/ACL en servidor y demostrar con el usuario de servicio que no puede crear/reemplazar current ni modificar código; comprobar escritura legítima y operación de aplicación/cola.
- Rollback: capturar ACL/modos antes del cambio y restaurar solo permisos necesarios si falla operación; no restaurar escritura del directorio de activación como solución permanente.
- Estado: abierto.

### SEC-002 — CI no verifica la identidad del VPS

- **ALTA / P0 / bloquea publicación mediante este workflow.** SUPPLY-02.
- Hecho: ci-deploy.yml:52 acepta automáticamente la clave observada en red. E-003.
- Impacto condicionado: atacante capaz de interceptar/redirigir esa conexión puede suplantar el VPS y recibir el artefacto o alterar la entrega. No se afirma robo de la clave privada ni MITM observado.
- Corrección: almacenar la clave pública/known_hosts verificada mediante consola del proveedor u otro canal independiente; no reconstruir confianza con una observación no autenticada en cada release. Mantener StrictHostKeyChecking.
- Responsable propuesto: CI/operaciones; antes del siguiente despliegue.
- Cierre: despliegue válido con clave fijada y rechazo controlado ante una clave diferente en entorno de prueba.
- Rollback: pausar despliegues si la clave cambia; verificar rotación fuera de banda y actualizar el valor, sin deshabilitar la comprobación.
- Estado: abierto.

### SEC-003 — Instalador descargado se ejecuta como root sin verificación previa

- **MEDIA / P1.** SUPPLY-02.
- Hecho: setup-server.sh:15 usa curl HTTPS pipe a php bajo root, sin verificar el instalador. E-002.
- Impacto condicionado: compromiso del canal de distribución/confianza TLS puede ejecutar código con privilegios máximos. HTTPS ofrece protección de transporte; no hay evidencia de compromiso.
- Corrección: descargar a temporal, verificar SHA-384/firma mediante procedimiento oficial y fallar cerrado antes de ejecutar; documentar procedencia/versionado.
- Responsable: operaciones; próximo bootstrap.
- Cierre: instalador alterado no ejecuta nada; instalador validado produce la versión prevista en host aislado.
- Rollback: conservar Composer previamente verificado; no ejecutar de nuevo código no validado.
- Estado: abierto.

### SEC-004 — Registro público sin limitador de frecuencia

- **MEDIA / P1.** AUTH-05.
- Hecho: routes/api.php:12 no tiene throttle; el grupo api no incorpora un limitador general propio y bootstrap/app.php solo configura Sanctum/admin. El login sí tiene throttle:6,1. E-005.
- Impacto: clientes que cumplen el flujo CSRF pueden generar cuentas repetidamente, consumir hashing/DB y espacio. CSRF no impide automatización por el propio cliente. No se probó carga ni creación masiva.
- Corrección: limitador nombrado e independiente para registro, límites de cuerpo/longitud de contraseña y cuotas proporcionadas; documentar política y comportamiento 429. La enumeración de email por unique es un riesgo residual distinto, sin recuperación implementada que auditar.
- Responsable: backend; antes de abrir registro público.
- Cierre: tests aislados verifican 429, separación del limitador de login/screener y registro legítimo funcional.
- Rollback: ajustar umbral mediante configuración, conservar protección antiabuso.
- Estado: abierto.

### SEC-005 — Cómputo interno acepta series sin tamaño máximo

- **MEDIA / P1.** APP-02.
- Hecho: IndicatorsComputeRequest y SignalsDetectRequest declaran bars:list[Bar] sin máximo; no hay límite propio de body en FastAPI. E-007.
- Impacto condicionado: caller interno comprometido o futura publicación accidental puede agotar memoria/CPU enviando series grandes. El loopback previsto reduce exposición; no se demuestra acceso público ni se envió carga maliciosa.
- Corrección: definir máximo de barras por contrato EOD y límite de bytes/request y concurrencia/tiempo; validar valores finitos y coherencia numérica cuando corresponda. Añadir credencial de servicio/TLS si cambia a comunicación entre hosts.
- Responsable: engine/backend; antes de operar datos no confiables.
- Cierre: payload dentro del límite funciona; exceso se rechaza de forma controlada sin cómputo costoso en entorno aislado.
- Rollback: ampliar límite tras medición de historia legítima, sin volver a tamaño ilimitado.
- Estado: abierto.

### SEC-006 — Plantilla web sin cabeceras de protección

- **BAJA / P2.** HTTP-01.
- Hecho: plantilla Nginx y middleware propio no declaran framing/CSP/nosniff/Referrer-Policy. E-013. Un CDN podría añadirlas, pero no hay evidencia de ese despliegue.
- Impacto: falta de protección adicional contra framing y uso inesperado de recursos. No demuestra XSS. HSTS se trata aparte: requiere primero verificar HTTPS completo.
- Corrección: nosniff, frame-ancestors o X-Frame-Options y Referrer-Policy; diseñar CSP a partir del build real, probar y aplicar tras validar recursos. Permissions-Policy para capacidades innecesarias.
- Responsable: frontend/operaciones; siguiente endurecimiento.
- Cierre: GET de SPA, errores y rutas relevantes devuelve las cabeceras previstas; chart, login y navegación siguen funcionando.
- Rollback: retirar/ajustar directivas incompatibles; usar Report-Only temporalmente sin presentarlo como política aplicada.
- Estado: abierto.
